# Copywriting & UX Writing Guide

Standard Operating Procedures for interface text, labels, and tone in Ant Design interfaces.

---

## Core Principles

1. **User-centered**: Write from the user's perspective
2. **Consistent**: Same terms, same grammar, same order
3. **Important first**: Lead with what matters most
4. **Professional**: Accurate, complete, precise
5. **Concise**: Friendly and positive, no filler

---

## Language Rules

### DO
- Use "You can..." instead of "The system allows you to..."
- Use "We" when responding to user complaints/suggestions ("We will review your feedback")
- Omit obvious words; don't repeat what users already know
- Use words familiar to users, not technical jargon
- Keep consistent word order in the same page/area
- Match operation names with target page titles
- Place important information first (or highlight with whitespace/bold)
- Explain benefits when asking users to take action
- Use Arabic numbers (faster to perceive than written numbers)
- Use sentence case in headlines, titles, labels, menus, buttons

### DON'T
- Don't mix "my" and "your" in the same sentence
- Don't use "can't" or "don't" when guiding users (feels commanding)
- Don't use absolute words ("never", "always") - makes users uncomfortable
- Don't capitalize entire words or phrases (harder to scan)
- Don't use exclamation marks unless for greetings/congratulations
- Don't add periods to standalone labels, titles, tooltip text, or table cells
- Don't use ambiguous time references ("recently", "soon") - be specific

---

## Error Messages

### DO
- Explain WHAT happened + WHY + WHAT TO DO next
- Use "Unable to complete" instead of "Failed" or "Error"
- Be specific: "Unable to save: file exceeds 5MB limit" not "Save error"
- Provide actionable next steps

### DON'T
- Don't say "Failure" or "Error" without context
- Don't blame the user ("You entered invalid data")
- Don't show technical error codes as the primary message
- Don't use exclamation marks in errors (creates anxiety)

---

## Button Labels

### DO
- Use **verbs** that describe the action result (Publish, Save, Delete, Login)
- For destructive actions, stress consequences: "Delete 12 records" not just "Delete"
- Keep labels short (1-3 words)

### DON'T
- Don't use nouns alone (use "Save Settings" not "Settings")
- Don't use vague labels ("OK", "Submit") when specific labels work better
- Don't use "Click here" or "Press this button"

---

## Tone by Context

| Context | Tone | Example |
|---------|------|---------|
| Success | Neutral, brief | "Changes saved" |
| Error | Supportive, helpful | "Unable to connect. Check your network and try again." |
| Warning | Clear, informative | "This action will remove all data from this project." |
| Onboarding | Friendly, inviting | "Welcome! Let's set up your workspace." |
| Empty State | Encouraging, guiding | "No projects yet. Create your first project to get started." |

---

## Punctuation Rules

### Omit periods for:
- Labels
- Titles and headings
- Input hints / placeholder text
- Tooltip text
- Single sentences in tables

### Use periods for:
- Multiple sentences or paragraphs
- Text before a link
- Full descriptions or instructions
